## 三、配置中标记为“无关联需求”的接口

| API | 配置状态 | 可能涉及的需求编号（候选） | 判断 |
|---|---|---|---|
| `FillGap` | 无关联需求 | 5.1.1.25 | **高置信度**：接口名称和功能是填补几何面间隙；该需求明确要求检测 gap、修复 unclosed loop、缝合未闭合 shell，达到实体水密。 |
| `FaceOffset` | 无关联需求 | 5.1.1.20 | **中置信度**：需求明确写有“表面偏移生成中面功能”；该接口可视为中面抽取的基础几何操作。原配置将其作为无关联接口，故这里只列候选，不改正式归属。 |
| `MergeSurface` | 无关联需求 | 5.1.1.13；5.1.1.25 | **中置信度**：接口描述为碎面合并。5.1.1.13 要求细小碎面一键合并，5.1.1.25 要求缝合面并保持拓扑共享；该接口可能是两类修复流程的底层或辅助操作。 |
| `FaceOffset(Extend)` | 无关联需求 | 5.1.1.20 | **低置信度**：面延伸不是需求文字中的明确接口，但可能作为中面/表面偏移前后的几何预处理；与 5.1.1.20 的关联仅为隐含候选，需接口负责人确认。 |

## 四、候选关联的使用建议

1. `FillGap` 建议优先由 5.1.1.25 的接口负责人确认；它与“gap / unclosed loop / sew unclose shell / 水密”语义高度一致。
2. `FaceOffset` 可作为 5.1.1.20 的辅助 API 候选，但不要替换配置中已有的 `MidSurface` 正式映射。
3. `FaceOffset(Extend)` 当前证据最弱，建议在 API 文档或调用链中确认其是否只是几何预处理接口。
4. `MergeSurface` 可能被 5.1.1.13（碎面合并）或 5.1.1.25（缝合与拓扑修复）间接调用；如需补充编号，建议由实现调用关系或测试用例证据决定。
